## 목표

약 1,000개 가족 그룹, 가구당 약 4명을 목표로 하되 고객의 실제 지식·벡터·권한·도구 실행은 고객
홈 서버 또는 에지가 소유하는 로컬 우선 제품 구조를 설계한다. 중앙 서비스는 계정·초대·결제·기기
동기화 조율·작업 접수·대기열을 맡고, 고비용 API 지식 주입은 비동기 큐와 별도 워커로 분리한다.

현재 단일 가정용 제품의 범위에는 포함하지 않는다. 실제 외부 제품화 결정과 단일 가정 운영
검증이 있기 전에는 중앙 서비스나 다중 tenant 기반을 선제 구현하지 않는다.

## 원칙

- 가족 그룹마다 데이터베이스를 1,000개로 분리하지 않는다. 중앙의 관리형 메타데이터·작업 데이터가
  필요하면 tenant 경계와 권한으로 격리한다.
- 중앙은 고객 원문 지식을 상시 보관하지 않는 선택지를 설계·평가 대상으로 남긴다.
- 동시 요청을 빠르게 접수하는 일과 즉시 고비용 분석을 시작하는 일을 분리한다.
- 로컬과 중앙의 데이터 소유권, 동기화 가능 범위, 오프라인·연결 복구 시 책임을 명시한다.
- 특정 클라우드, 메시지 시스템, 데이터베이스, 에지 구현에 고정하지 않는다.

## 단계

1. 가족 그룹, 사용자, 기기, 홈 서버/에지, 중앙 계정의 identity·tenant 경계와 권한 전파를 모델링한다.
2. 중앙 메타데이터·결제·초대·작업 상태와 로컬 원문·벡터·권한·도구 실행의 소유권을 데이터 흐름으로 확정한다.
3. 중앙 원문 미보관, 제한 보관, 관리형 보관 대안을 프라이버시·복구·지원·비용 관점에서 평가한다.
4. 작업 접수, 큐잉, 워커 실행, 결과 전달을 분리하고 idempotency key, 재시도, 취소, dead-letter/운영 복구 정책을 정의한다.
5. tenant별 동시성·작업량·API 사용량·비용 한도와 공정한 대기 정책을 정한다.
6. tenant·작업 단위 관측성, 감사, 장애 격리, 데이터 접근 점검과 목표 규모 부하 평가 기준을 만든다.

## 완료 조건

- 약 1,000개 가족 그룹과 가구당 약 4명이라는 목표에서 tenant 격리·권한 경계·데이터 소유권이 명확하다.
- 로컬은 실제 지식·벡터·권한·도구 실행을 소유하고, 중앙의 역할은 조율·계정·결제·작업 운영으로 제한된다.
- 동시 요청 접수와 고비용 처리의 분리, 작업 제한, 재시도, 멱등성, 취소와 복구 동작이 정의된다.
- tenant별 사용량·비용 한도, 감사·관측성, 과부하와 장애의 격리 기준이 검증 가능하게 문서화된다.
- 중앙 원문 상시 보관 여부가 구현 관성이 아니라 명시적 제품·프라이버시 결정으로 남는다.

## 제외 범위

- 1,000개 독립 데이터베이스 또는 가족별 전용 중앙 인프라의 선제 구축
- 중앙 서비스가 모든 고객 원문·벡터를 기본적으로 복제하는 설계
- 특정 큐, 클라우드, 에지 런타임의 실제 배포 구현
