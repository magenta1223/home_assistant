# 인덱싱과 배치 실패 재시도

- 상태: TODO
- 목표: Weekend MVP 이후

## 문제

벡터 인덱싱과 memory 배치 실패는 로그만 남기고 성공 흐름을 계속한다. 실패 작업을 다시 실행하는 worker나 사용자 명령이 없어 DB와 검색 인덱스·트리가 영구적으로 달라질 수 있다.

## outbox란

DB 변경과 함께 나중에 외부 시스템에서 실행할 작업을 같은 transaction에 기록하는 작은 작업 목록이다. 예를 들어 memory 저장과 함께 `INDEX_MEMORY 123`을 기록하고 별도 worker가 성공할 때까지 재시도한다.

## 계획

1. 우선 실패를 숨기지 않고 memory ID와 실패 단계를 구조적으로 기록한다.
2. 재시도 대상은 `INDEX_MEMORY`, `PLACE_MEMORY_BATCH` 두 종류로 제한한다.
3. outbox, 상태 테이블, 수동 repair command 중 가장 단순한 방식을 구현 시점에 선택한다.
4. 재시도 횟수, 마지막 오류, 다음 재시도 시각을 저장한다.
5. 같은 작업을 여러 번 실행해도 결과가 같도록 idempotent하게 만든다.
6. 실패 작업 수를 health 또는 운영 로그에서 확인할 수 있게 한다.

## 완료 조건

- Ollama, Qdrant, Codex의 일시 장애 후 자동 또는 명시적 재시도가 가능하다.
- 성공했다고 응답한 memory가 영구적으로 검색 불가능한 상태에 남지 않는다.
